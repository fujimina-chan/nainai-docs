# Architecture Decision Records (ADR)

## 目的

ADR（Architecture Decision Record）は、nainai プロジェクトにおける **重要な技術判断・設計判断** を記録するための文書です。

- なぜその判断をしたのか（背景・文脈）
- どのような選択肢があったか
- 何を決定したか
- その判断がもたらす影響

を残すことで、将来の開発者が判断の根拠を理解し、必要に応じて見直しやすくします。

## 基本形式

各 ADR は `adr/` ディレクトリ配下に、連番付きの Markdown ファイルとして作成します。

```text
adr/
├── README.md           # このファイル
├── 0001-<title>.md
├── 0002-<title>.md
└── ...
```

### テンプレート

```markdown
# ADR-NNNN: <タイトル>

## ステータス

<提案中 / 承認済 / 非推奨 / 置換済>

## コンテキスト

<判断が必要になった背景・問題>

## 検討した選択肢

<検討した代替案とその概要>

## 決定

<採用した方針>

## 結果

<この決定による影響・トレードオフ>
```

## 運用

- 新しい ADR を追加する際は、連番をインクリメントする
- 既存の ADR を無効化する場合は、ステータスを「非推奨」または「置換済」に更新し、後続 ADR への参照を記載する
- ADR の本文は nainai-docs を正本とし、実装リポジトリ側には ADR 番号への参照のみを残す
- 内容の異なる意思決定は、不自然に 1 ファイルへまとめず分割する
